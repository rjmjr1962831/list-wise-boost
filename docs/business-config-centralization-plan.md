# Business Config Centralization: Plan & Risk Analysis

**Status:** Plan only — no code changes yet  
**Created:** March 2026  
**Purpose:** Centralize star rating, review count, years in business, pricing, and other business numbers into a single config so all consumers draw from one source of truth.

---

## 1. Executive Summary

Today, merit gate values (4.5+, 10+, 5yr), pricing ($0 / $100 / $150), funnel stats (670,000+, 882, 0.4%), and state totals are scattered across 50+ files in React, Edge Functions, static HTML, Python scripts, SQL migrations, and FAQ data. Changing one number requires a manual grep-and-replace across many layers. This plan proposes a single JSON config as the source of truth, with clear consumers and migration steps.

## 4. Consumer Matrix & Access Strategy

| Consumer | Runtime | How to Access Config |
|----------|---------|------------------------|
| React / Vite | Node | `import config from '@/config/businessConfig.json'` |
| Supabase Edge Functions | Deno | Read JSON from deployed file or inline in function |
| Python `generate_clean_rooms.py` | Python | `json.load(open('config/businessConfig.json'))` |
| Static HTML (public/*) | Build-time | Vite plugin or script injects at build |
| FAQ (`faqFull.ts`) | Build | Import config, interpolate in strings |
| SQL migrations | Deploy-time | No runtime config; migration updates hardcoded values when config changes |

### Edge Function Constraint

Deno cannot import Node modules. Options:

1. **Inline a minimal config** in each Edge Function that needs it (duplication, but explicit).
2. **Deploy config alongside functions** — e.g. `supabase/functions/_shared/config.json` and `Deno.readTextFile` or import from relative path.
3. **Fetch from public URL** — e.g. `https://www.top10lists.us/config/business.json` (adds network dependency, cache considerations).

**Recommendation:** Option 2 — shared JSON in `supabase/functions/_shared/` (or similar) that gets deployed with functions. Deno can read local files.

## 5. Implementation Plan (Phased)

### Phase 1: Create Config & React Adoption (Low Risk)

1. Create `src/config/businessConfig.json` with all variables.
2. Create `src/config/useBusinessConfig.ts` — typed loader + derived helpers (e.g. `getMeritReviewsLabel()`).
3. Migrate `meritGate.ts` to re-export from config (keep same exports for backward compatibility).
4. Update React consumers one-by-one: `Transparency`, `RankingMethodology`, `QualificationGates`, `ProfessionalCard`, `CheckProfile`, `VisibilityTiersPage`, `CleanRoomAgentArticle`, etc.
5. Update `faqFull.ts` and `cityFaqSchema.ts` to use config.
6. Regenerate FAQ JSON: `npm run generate:faq`.

**Deliverable:** All React and FAQ copy use config. No behavior change.

### Phase 2: Edge Functions

1. Add `supabase/functions/_shared/businessConfig.json` (copy or symlink from source).
2. Add `supabase/functions/_shared/config.ts` that loads and exports config.
3. Update `serve-bot-content-html`, `serve-bot-list-html`, `serve-bot-agent-html` to use shared config.
4. Update `sanitizeMeritGate()` to use config-driven regex (or remove if all content is fresh).

**Deliverable:** Edge Functions no longer hardcode merit gate or funnel stats.

### Phase 3: Static HTML & Python

1. Update `generate_clean_rooms.py` to read `config/businessConfig.json` (or `src/config/businessConfig.json`). Fix **current bug**: it still uses 4.8/20 in `fetch_agents`.
2. Add build script or Vite plugin to inject config into `public/transparency.html` and other static HTML at build time (or replace static HTML with Edge Function–served content where possible).
3. For pre-generated `public/clean-room/*.html` — either regenerate from Python (which now uses config) or migrate to Edge Function–served pages.

**Deliverable:** Python and static HTML use config.

### Phase 4: SQL & Documentation

1. Document in `MASTER_KNOWLEDGE_DOCUMENT_TODAY.MD` that config is source of truth.
2. Add rule: "When merit gate or other business numbers change, run a migration to update SQL functions."
3. Create migration template/checklist for SQL updates (e.g. `enqueue_professional_for_pipedrive_sync`, `get_neighborhood_ids_with_qualified_agents`, `get_neighborhood_active_agents`).

**Deliverable:** Clear process for keeping SQL in sync with config.

## 6. Risk Analysis

### 6.1 High Risk

| Risk | Mitigation |
|------|------------|
| **Edge Function config not available at runtime** | Test locally with `supabase functions serve`; verify config file is present in deployed bundle. |
| **SQL out of sync with config** | Document migration step; add CI check that greps SQL for hardcoded 4.5/10 and fails if config differs (optional). |
| **Stale static HTML after config change** | Either regenerate (Python) or serve via Edge Function. Add "config version" or "last updated" to pages. |

### 6.2 Medium Risk

| Risk | Mitigation |
|------|------------|
| **Python script run without config file** | Use repo-root path; fail fast with clear error if file missing. |
| **Build order** — config must exist before Vite build | Config is committed; no build-time generation. |
| **Type safety** — JSON has no types | Add TypeScript interface in `useBusinessConfig.ts` and validate at load. |

### 6.3 Low Risk

| Risk | Mitigation |
|------|------------|
| **Config typo** | Schema validation (e.g. Zod) in loader. |
| **Multiple config copies drift** | Single source; Edge Functions use symlink or copy in CI. |
| **Legacy 4.8/20 in DB content** | `sanitizeMeritGate()` already handles; can be config-driven. |

### 6.4 Known Gaps (Accept or Defer)

| Gap | Recommendation |
|-----|----------------|
| **Database-stored content** (`writeup_html`, `marketing_content`) | Keep `sanitizeMeritGate()` for old content; new content generated by LLMs should use config in prompts. |
| **Legacy migration** `20260210_sitemap_qualified_neighborhood_ids.sql` | Still references 4.8/20 in comments; update in Phase 4 doc pass. |
| **`generate_clean_rooms.py` fetch_agents** | Uses 4.8/20 — **fix in Phase 3** (critical bug). |

## 7. Out of Scope (For Now)

- Pricing tiers (Bronze/Silver/Gold/Platinum) — different domain, already in `types/pricing.ts`.
- Competitor pricing (Zillow $300–5000, RealTrends $195/year) — marketing copy, not business config.
- Scoring weights — could be config but lower priority than merit gate.

## 8. Success Criteria

1. **Single change** — Update `merit.minRating` in config → all React, Edge Functions, Python, and FAQ reflect it.

3. **No hardcoded 4.5, 10, 5, 100, 150** in merit/pricing context except in config and SQL (with migration).
4. **Verification** — Grep for "4.5" and "10+" in merit context returns only config + generated output.
